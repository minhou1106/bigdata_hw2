## Model and time controls

The reported model is **control4_push2**, six independent CatBoost binary classifiers. Each input has 34 features: a constant and three user-age transforms, plus four log-count windows (1/7/28/90 days) and one recency feature for each activity. Counts join activity actor foreign keys to `Users.user_id`. Raw IDs and text do not enter as numeric features. Issues that represent PR conversations do not count as new issues.

This is relational aggregation, **not a GNN**. It does not learn all 20 foreign-key relations. `Repositories` is checked as part of the eight-table snapshot, but its attributes do not enter the selected 34-dimensional feature vector. The core also constructs extra coverage/repository statistics for unused candidate settings; `control4` consumes only `base`.

Features require both event time and row availability before `t-4h`. PRs/issues/reviews use `first_seen_at` to censor row availability. No merged/closed/dismissed mutable-state columns enter the selected features. Training labels must be visible before the simulated fit cutoff. Train, early-stop, calibration and evaluation weeks are chronologically separate. Four-hour exclusion is our conservative modeling choice, not a claim that the revised assignment mandates it.

Each activity's daily coverage screen compares observed counts with 10% of the preceding 28-day median, requiring at least 14 reference days and positive counts/reference. This is a heuristic. A suspicious day excludes its entire overlapping label week for that activity. It cannot prove that other days or activities are complete.

The first five activities use four training weeks, one early-stop week and one threshold-calibration week. In the original short-lead study, Push had only four eligible historical weeks, so it used **two training weeks**, one early-stop week and one calibration week. The early-forecast strategy keeps that frozen two-training-week setting. Its shifted formal target grid has six eligible Push weeks; it selects only the latest four for train/early-stop/calibration. Activity-specific schedules can therefore differ. No unknown labels are filled with zero as a fallback. Each threshold maximizes binary F1 on that activity's earlier calibration week; this is not direct optimization of the joint macro/micro score.

CatBoost settings: depth 5, learning rate 0.05, L2 5, maximum 600 iterations, patience 50, four CPU threads, train-only positive class ratio capped at 15. Earlier raw history contributes to features but does not make every downloaded week a training label week. Early August history is truncated by the August 1 collection boundary.

## Results and limitations

The controlled study uses identical data, dates, seeds and classifier settings. `full34` reproduces the original run. `user_age4` removes all related activity features. `activity90_7` keeps only a constant and six 90-day counts, removing age, recency and short windows together. Neither experiment isolates a single causal feature effect. Baseline `previous_week` copies visible activity in the preceding seven-day window, ending at `t-4h`.

| Method | Mean observed six Score | Mean five-activity sensitivity |
|---|---:|---:|
| CatBoost full34 | 0.2832 | 0.3786 |
| CatBoost user_age4 | 0.1117 | 0.1148 |
| CatBoost activity90_7 | 0.2674 | 0.3707 |
| Previous visible week | 0.3031 | 0.3415 |
| All zero | 0.0000 | 0.0000 |

The previous-week baseline exceeds CatBoost on the **observed six-activity** metric. CatBoost exceeds it on the five-activity sensitivity. These are different tasks under incomplete labels, so we do not claim CatBoost is universally best. The five-activity metric excludes Push for sensitivity only and is not an official missingness mask. Two seeds on one week are not two independent validation weeks. All periods are inspected development, not an unseen final test. Latest-snapshot backfills, missingness and observed-cohort selection can bias evaluation. See `results/feature_study.csv` for unrounded values.
